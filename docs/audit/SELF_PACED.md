# Self-paced publication and content history

Phase 5 connects the student catalog to published offer metadata instead of deriving discovery from private enrolled content. Catalog responses contain counts and descriptions, never lesson bodies, video links or answer keys. Checkout/free enrollment reloads the private core from the server so the first lesson appears immediately after confirmed access.

The course workspace's **Enrollment & publishing** panel creates a self-paced offer, sets an INR price (0 means free), saves a draft, publishes after content validation, or closes enrollment. All active modules must contain lessons; reading/lab content must be non-empty and video lessons must have ready assets. Multiple offers require explicit selection; the legacy course-only enrollment API refuses ambiguous offers rather than choosing a price arbitrarily. Changes to lessons/modules/media return the course and published self-paced offers to Draft. Reordering alone retains publication because it preserves valid content and lesson identities.

Apply additive migration `0010_safe_content_history.sql`. Existing rows remain active. Removed lessons/modules receive `archived_at`; course removal sets `deleted_at` and Archived status. Existing progress, purchases, media, credential records and revisions remain stored. Closing a course's enrollment does not revoke existing learners' access. Archived lessons leave the active curriculum and cannot be completed or played through learner endpoints.

Each lesson edit/replacement/archive/restore stores its prior snapshot in `lesson_revisions`. Replacing video requires a successfully processed asset in the same course, then switches the lesson's asset atomically. Progress remains tied to the stable lesson ID. Reorder requests must include every active module/lesson exactly once; they lock the course and move positions through an unused temporary range, so unique position constraints remain enforced.

The upload UI can replace an existing video lesson without first creating an empty lesson. It exposes processing failures and attaches only after readiness. Course authoring no longer invents starter content or reports success after a failed content request. The up/down controls persist ordering on the server; student progress survives both moves and replacements.

Recovery APIs, authenticated as admin: `GET /api/admin/courses/:id/lessons/:lessonId/history`, `POST /api/admin/courses/:id/lessons/:lessonId/restore`, and `POST /api/admin/courses/:id/restore`. Lesson restore restores the current archived row and its module; historical revision snapshots remain available for explicit review and recovery. It does not automatically reinstate every archived sibling or silently roll back a media asset. Republish after review. No existing content was archived or rewritten in development/production during implementation.

`self-paced.test.ts` deliberately runs against schema only, with no seed content. It authors an original course, rejects premature publication, attaches a ready media fixture, publishes a paid offer, confirms a fake-provider purchase, denies another learner playback, preserves independent lesson progress, reorders, replaces, archives, restores, and completes the course. The media fixture does not run transcription; real FFmpeg and explicit transcription failure are covered separately in phase 2. The existing simple certificate path works for this assessment-free fixture; versioned policy enforcement and serialized certificate issuance are replaced in phase 8, so phase 5 alone is not the final certificate-security acceptance.
